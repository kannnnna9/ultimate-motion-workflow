# UMP M3 Web Karaoke Implementation Plan

**Goal:** Add a deterministic, editable web-karaoke subtitle mode to the custom renderer and keep “Kejaksaan Agung” together without changing the approved VO.
**Architecture:** Keep the validated word timeline and render clock authoritative. Generate a revision-bound karaoke sidecar with balanced phrase groups, then let the isolated browser recorder draw a single shadow-DOM overlay at each exact frame seek; retain ASS/FFmpeg and no-subtitle paths unchanged. Burn web karaoke during browser capture and keep the existing audio mux.
**Tech stack:** Python 3.11, Node 22, Playwright Core, Chrome/SwiftShader, FFmpeg/FFprobe, unittest.
**Spec:** `docs/ultra/specs/2026-11-26-ump-m3-karaoke-design.md`; parent M3 contracts in `docs/ultra/plans/2026-11-26-ump-v2.0-m3-audio.md`.

## Global Constraints

- Keep defaults at 1080×1920, 30 FPS, H.264; do not silently shorten, rescale, lower FPS, or degrade audio.
- Silent/no-speech/no-subtitle remains a valid path and must not invoke TTS, ASR, alignment, or subtitle generation unnecessarily.
- Preserve approved script text and the exact, hash-bound audio/timeline. Never repair a subtitle defect by changing or regenerating the VO.
- Use the validated integer-millisecond word timeline and absolute frame time; do not use wall-clock timers or free-playing CSS animation for capture.
- Enforce exactly one speech-subtitle owner. Karaoke is web-rendered; `draws_speech_text=true` is rejected for ASS and web karaoke.
- Preserve offline/network-denied rendering, private workspaces, bounded runtime/storage, clean failure, immutable revision hashes, and the legacy/none/ASS behavior.
- Do not modify the installed production plugin, merge, push, publish, or deploy.
- Keep the root free-space reserve at 5 GiB, DATA_ROOT below its 2 GiB soft threshold, and renders serialized; check both before the real render.

## File Map

- `ump_core/composition.py`: normalize `subtitle_mode` as `none|ass|web`, require `subtitle_effect="karaoke"` only for web mode, and validate effect/enable/voice/duplicate-owner agreement.
- `ump_core/jobs.py`: include web karaoke among modes that require approved-script timing and pin the exact approved naskah hash in the revision.
- `ump_core/subtitles.py`: implement shared no-orphan phrase grouping plus deterministic validation/serialization of the editable web-karaoke JSON sidecar; keep ASS generation deterministic and compatible.
- `scripts/record_custom.mjs`: validate the optional karaoke sidecar, mount the isolated browser overlay, and update active word state from each absolute seek before screenshot capture.
- `ump_core/worker.py`: request timing for web karaoke, generate/stage/verify the sidecar, pass it to the recorder, publish it as the one subtitle artifact, and include it in source bundle hashes; leave ASS FFmpeg burn-in exclusive to ASS mode.
- `tests/test_subtitles.py`: phrase grouping, karaoke JSON, timing/hash validation, and no-orphan regression.
- `tests/test_composition.py`, `tests/test_jobs.py`: mode/effect/owner validation and revision normalization/pinning.
- `tests/test_worker.py`, `tests/test_custom_renderer.py`: required timing, deterministic word transitions, shadow overlay rendering, one-owner and artifact/bypass/failure integration.
- `docs/ultra/plans/2026-11-26-ump-v2.0-m3-karaoke.md`, `docs/verification/ump-v2-progress.md`, `skills/motion-pipeline/SKILL.md`, `CHANGELOG.md`: exact instructions, measured proof, review state, and unreleased change.

## Dependency Graph

T1 → T2 → T3 (single serial lane: schema and sidecar precede recorder handoff; real render/docs follow the integrated code).

## Lanes

- Single serial lane. `composition.py`, `subtitles.py`, `worker.py`, and `record_custom.mjs` share one contract and must not be implemented in parallel.

## Review Focus

1. **Mode mismatch/legacy breakage:** old `none` and `ass` payloads normalize exactly; `web` without the karaoke effect, voice track, or required timeline fails before artifact publication.
2. **Duplicate speech owner:** ASS/web karaoke plus declared in-scene speech text is rejected; no duplicate subtitles appear in the MP4.
3. **Clock drift and seek nondeterminism:** active word is selected from absolute frame time, including repeat/reverse seeks and a sub-frame word gap; no live timer advances it.
4. **Untrusted caption text / CSS interference:** word text is inserted as text (not HTML), overlay is isolated from scene CSS/DOM, external requests remain blocked, and layout respects phone margins.
5. **Partial/stale artifacts:** mismatched timeline/audio hash, malformed sidecar, browser/FFmpeg failure, or a stale render publishes neither MP4 nor subtitle/source artifacts.

### Task 2: Deterministic browser karaoke layer and worker artifact handoff

**Files:** modify `scripts/record_custom.mjs`, `ump_core/worker.py`, `ump_core/tools.py`, `tests/test_custom_renderer.py`, `tests/test_worker.py`.

**Interfaces:**
- `worker._needs_speech_timing` and recorder `readProject` treat both ASS and web karaoke as requiring the timeline;
- The worker writes `subtitles.json` from `render_karaoke_subtitles`, validates the sidecar against the pinned voice/timeline, passes it to the recorder, and publishes exactly one `subtitles` artifact. Include identical bytes/hash in `source.zip` and `manifest.json`. For web mode, do not pass an ASS subtitle filename to the final FFmpeg mux; its video frames already contain the web layer.
- The recorder mounts one closed-shadow-root overlay after `UMP.ready()`/`UMP.setTimeline()` and before the first seek. It builds nodes with `textContent`, fixed bundled CSS, no external resources, and a private update callback. On each frame, call scene `UMP.seek(t)`, update karaoke state from the same absolute frame time, wait for paint, then capture. The overlay shows the phrase group; only the active word is orange. A gap shorter than one 30-FPS frame holds the previous word until the next word’s first sampled frame; longer gaps have no active word. No timers or playback-rate clock.
- `none` creates no timing/subtitle artifact; `ass` keeps current timeline and one FFmpeg burn; web karaoke keeps AAC mix and burns only in browser capture.
