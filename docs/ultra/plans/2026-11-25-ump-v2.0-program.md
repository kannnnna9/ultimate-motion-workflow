# UMP v2.0 Program Implementation Plan

**Goal:** Deliver UMP v2.0 as a creative-first, adaptive video workflow that produces original, seekable vertical videos and preserves v1 projects and approvals.

**Architecture:** Extend the existing UMP job, approval, renderer, and data-root infrastructure; add a job-owned custom web composition as the default production path while retaining the v1 preset/card path as explicit legacy compatibility. Use HyperFrames when a composition passes compatibility probes, the native recorder when it is the better fit, and FFmpeg for encode/mux. Keep each new capability small and prove it with real rendered work before broadening it.

**Tech stack:** Python 3.11.16; Node 22.22.2; Playwright Core 1.65.1; HyperFrames 0.9.72; Chrome 156.0.8078.47 with SwiftShader; FFmpeg 6.1.1; unittest. WhisperX and faster-whisper are not installed. Runtime versions are the M0 profile, not universal deployment pins.

**Spec:** `docs/ultra/specs/2026-11-25-ump-v2.0-master-blueprint.md` (operator-approved blueprint; only Markdown line-break whitespace was normalized in the committed copy; SHA-256 below identifies the original supplied file: `38bcaa1df0a22921c4e3c6d3f95f1f09298b7fabc77982d2df5de8814f068763`).

## Global Constraints

- The approved blueprint is the design authority. Earlier staged-pipeline and pipeline-repair plans are historical; where they conflict, v2.0 decisions win. Preserve working v1 behavior rather than applying old plans as a downgrade.
- **Custom composition is the default.** Presets and the v1 card builder remain optional compatibility tools, never a content or action ceiling.
- Do not use Blender. Remotion, paid services, local heavyweight image generation, a vector database, and separate creative agents are not required.
- ADR-010 Series Continuity Engine and cross-episode canon are deferred and are not release blockers.
- Default final canvas is 1080×1920 at 30 FPS; 60 FPS is optional. No hidden resolution, timing, asset, or quality downgrade.
- Research, narration, audio, music, subtitles, and source cards are conditional on the brief. Silent and no-subtitle projects are valid.
- Treat scene code, imported HTML, assets, and upstream material as untrusted. Render without Hermes credentials, allow writes only in a job workspace, deny network during capture, validate paths/symlinks, and apply CPU/RAM/time plus an explicit storage budget. Fail closed when isolation is unavailable.
- Keep approved artifacts immutable and bind approvals to the exact revision/artifact. Recompute only affected dependencies when safe; never preserve stale approval or stale cache as current.
- Do not modify the production plugin/data root, merge to `main`, push, publish, or deploy without operator approval. No paid service or destructive migration without approval.

## Lanes

- **Single serial lane.** Worker, job, renderer, and artifact contracts share files and state; parallel implementation would create avoidable interface drift. Source study can be batched, but its findings must be reviewed before code is changed.
- Before coding a milestone, commit its focused `ultra:plan` task plan with exact files, tests, commands, and expected results. The operator has already authorized proceeding through M0–M5; no extra architecture approval is needed unless a locked decision, paid service, destructive migration, or production side effect becomes necessary.

## Review Focus

1. **Custom path quietly falls back to fixed cards.** Add a job-level test proving an authored composition reaches the renderer without `_cards`, a preset HTML file, or a topic-specific template.
2. **Random seek or retry produces a different/stale frame.** Test cold load plus forward, reverse, repeated, and nonsequential seeks against the same frame index and source snapshot.
3. **Scene code reaches secrets, host files, or the network.** Test that a secret outside the allowlist is unreadable, writes outside the render workspace fail, IPv4/IPv6 sockets and remote asset loads fail, and the job still renders offline.
4. **Optional media becomes accidentally mandatory or duplicates.** Test silent/no-subtitle jobs bypass ASR and emit no captions; test one enabled subtitle owner and real speech timing separately.
5. **Revision/cache/approval state becomes stale or over-invalidates.** Test changed source hashes invalidate relevant outputs and approvals, unchanged artifacts keep their hashes, stale runs cannot publish, and rollback restores an approved snapshot.

## M0 Follow-up — DATA_ROOT Storage Policy (2026-11-26)

**Live baseline:** root filesystem is 50 GiB total, 36 GiB used, 12 GiB available (76%); `~/.hermes/ump-v2` is 23 MiB (runs 23 MiB; jobs 320 KiB; fixtures 304 KiB; assets 108 KiB; evidence 16 KiB); `/dev/shm` is 3.8 GiB with 24 KiB used; RAM available is 4.8 GiB. The DATA_ROOT tree contains only development fixtures, versioned assets, job revisions, run artifacts, and evidence; the M0 rollback backup remains separate and must be preserved.

**Aggregate budget:** 2 GiB soft threshold (warn and pause new large installs/benchmark runs for an inventory); 3 GiB hard threshold (do not start any new render/install that writes to DATA_ROOT). The existing 512 MiB per-render MP4 ceiling, 2 GiB memory-accounted `/dev/shm` unit, serialized render lock, 900-second runtime limit, 128 MiB immutable asset-library cap, and 40 MiB composition-pinned-asset cap remain independent limits. There is no automated aggregate DATA_ROOT quota guard yet: until one is implemented and tested, the 2/3 GiB thresholds are mandatory manual preflight/stop gates, not claims of automatic enforcement.

**System reserve and start gate:** preserve at least 5 GiB free on `/`; stop large installs and benchmark renders if the planned dependency/output footprint would cross that floor. Before every long render/install, measure both `df -h /` and `du -sh ~/.hermes/ump-v2`, require DATA_ROOT below 2 GiB, run only one render at a time, include caches and source bundles in projected usage, and do not lower resolution/FPS to fit. Short 6–8 second proof renders may proceed only when the actual disk/memory preflight passes and the per-run controls remain enabled. Current baseline passes these manual gates.

**Ruling:** use a manual 2/3 GiB aggregate stop gate and preserve a 5 GiB system reserve now; do not invent automatic deletion or a broad cleanup command for user-owned revisions/assets/runs. Cost if wrong: work pauses at 2 GiB until exact cleanup is reviewed; an enforced aggregate guard must be added before larger M4/M5 batches.

**Retention and cleanup:** never automatically delete job inputs/revisions, the asset catalog or immutable version blobs, approved outputs, source bundles/manifests, evidence, or rollback backups. No age-only, wildcard, or recursive deletion. Cleanup candidates are limited to exact run IDs for failed/incomplete work or superseded unapproved previews after confirming no active worker/unit/lock, no live approval target, and a retained pinned revision that can reproduce the artifact. Inventory paths and hashes first; move only the named run directory to same-filesystem quarantine for at least 7 days; permanent deletion requires operator confirmation for the exact IDs. Recheck DATA_ROOT and root free space afterward. Remove a generated cache only after confirming no worker is active and that the exact cache is regenerable; count it toward the aggregate budget until removed.

**M0 follow-up status:** the policy is now defined; it is operational/manual, not aggregate-quota code. Per-render output and tmpfs bounds are enforced by the M1 worker. Revisit automated aggregate enforcement before M4 concurrency/resource tests or any multi-benchmark batch. The installed production plugin's two local flat-vector edits and the M0 rollback backup remain untouched.
