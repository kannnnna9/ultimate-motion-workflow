# UMP v2.0 M2 — Asset & Motion Intelligence Plan

**Goal:** Add a small reusable, provenance-aware asset library to custom compositions and prove it with two original renders containing meaningful articulated motion.

**Architecture:** Keep assets as immutable, versioned files under the existing `DATA_ROOT`, with a JSON catalogue rather than a database. A composition pins exact asset IDs, versions, and hashes into its revision; the worker verifies and stages those files offline, and the source bundle carries the files plus provenance manifest. Support procedural SVG authoring and Telegram image import, while keeping the renderer and asset library optional to legacy jobs.

**Tech stack:** Python 3.11-compatible stdlib; existing job/revision store; SVG/PNG/JPEG; existing Playwright Core 1.65.1 recorder; FFmpeg; `unittest`. Optional evidence renders use the already-existing InstaBox free machine (4 vCPU/8 GiB, 20 GiB persistent disk); no new machine, paid tier, or production deployment.

**Spec:** `docs/ultra/specs/2026-11-25-ump-v2.0-master-blueprint.md`, §§7, 13, 14 M2, 16 G5/G11.

## Global Constraints

- Asset registry/cache minimum: ID, version/hash, type, format/path, source/provider, provenance/license, generation parameters/seed when relevant, and lock status.
- Use approved asset versions; never replace files silently. Validate access, file type, and dimensions; do not add a database or complex asset service.
- Imported HTML, assets, and scene code are untrusted. Render with no Hermes credentials, deny network during capture, allow only staged workspace files, and fail closed on isolation failure.
- Default final canvas is 1080×1920 at 30 FPS; do not silently change resolution, FPS, timing, or quality to shorten renders.
- External generation is optional; no local heavyweight image model, paid service, or Blender dependency. ADR-010 cross-episode canon remains deferred.
- Preserve M1 job/revision approval binding, immutable snapshots, source-bundle verification, and v1 compatibility.
- Bound the reusable asset library to 128 MiB of stored version blobs and 256 catalogued versions; count orphan blobs during crash recovery, reject over-quota publication, and never auto-delete immutable asset history.
- No merge, push, publish, production-plugin replacement, or deployment. Do not create or resize an InstaBox machine.

## Review Focus

1. **A changed or locked library item mutates an old composition.** Test exact version/hash pinning, immutable revision copies, locked-version rejection, and hash mismatch failure before capture.
2. **Asset bytes escape the format/size boundary or concurrent writers corrupt history.** Test invalid image signatures, malformed dimensions, unsafe/external/scripted SVG, traversal IDs, symlinks, empty files, per-asset/aggregate byte limits, and concurrent version allocation.
3. **Browser reads an unstaged file or remote URL.** Extend the real isolated browser test to load a staged local image and to reject a local-file escape plus external network request.
4. **M1 payloads and legacy renderer regress.** Existing no-asset compositions and legacy fixtures must still render unchanged; absent `assets` means an empty pinned set.
5. **Asset inclusion is metadata-only or motion is merely translation.** Inspect actual output and source linkage; prove an articulated part changes pose across timestamps and play the encoded MP4 at normal speed.

## Task 1: Add the bounded asset catalogue and author/import operations

**Files:** create `ump_core/assets.py`, `tests/test_assets.py`; modify `ump_core/tools.py`, `plugin.yaml`, `tests/test_composition_tools.py`.

**Interfaces:**
- `AssetStore(root).add_svg(asset_id, svg, *, source, provenance, license, seed=None, parameters=None, locked=False) -> record` stores validated UTF-8 SVG as an immutable version and returns `{id, version, sha256, media_type, size_bytes, source, provenance, license, seed, parameters, locked}`.
- `AssetStore(root).add_image(asset_id, data, filename, *, source, provenance, license, locked=False) -> record` accepts validated PNG/JPEG bytes only; the tool obtains bytes exclusively from the current authorized Telegram image cache using `O_NOFOLLOW` and the existing 20 MiB attachment ceiling.
- `AssetStore(root).list() -> list[record]` returns metadata only. Re-registering identical content and metadata is idempotent only after verifying the stored file's type, size, and hash. Changed bytes under a locked ID fail with `ASSET_LOCKED`; metadata-only corrections may create a new version only with the same content hash and inherit the lock. Writers serialize version selection and recover or safely skip orphan version blobs. Metadata limits: source ≤256 chars, provenance ≤1,024, license ≤256, canonical parameters ≤16 KiB; library ≤128 MiB total and ≤256 versions, no automatic deletion.
- SVG is self-contained, has bounded declared/viewBox dimensions, and rejects DTD/entity, script/event handlers, `foreignObject`, external references (including escaped CSS tokens), and animation. PNG dimensions/chunks and compressed scanline structure, plus JPEG frame/scan structure, are validated without third-party packages; reject zero, malformed, or >16-megapixel images. Limit each stored asset to 10 MiB and a composition's pinned assets to 40 MiB.
- `ump_assets` exposes `list`, `create_svg`, and `import_image`; `source`, provenance, and license are required and never inferred. `create_svg` records the caller's seed and JSON parameters without claiming that metadata alone regenerates the bytes.

## Task 2: Pin assets in composition revisions and the isolated render bundle

**Files:** modify `ump_core/assets.py`, `ump_core/composition.py`, `ump_core/jobs.py`, `ump_core/worker.py`; modify `tests/test_assets.py`, `tests/test_composition.py`, `tests/test_composition_tools.py`, `tests/test_jobs.py`, `tests/test_custom_renderer.py`.

**Interfaces:**
- Composition input may omit `assets` (backward-compatible empty list) or provide unique `{id, version}` references. Reject filesystem paths, unknown IDs/versions, duplicate IDs, and more than 40 MiB total.
- `AssetStore.resolve(asset_id, version) -> (record, bytes)` resolves one exact version under the catalogue lock and returns only bytes whose regular-file type, size, and SHA-256 match the record.
- `JobStore.write_composition(...)` resolves each requested version and stores its immutable bytes under `revisions/<rev>/composition/assets/<id>-v<version>.<ext>`; the revision `project.json` asset manifest records the relative path, content hash, and full provenance/license/lock metadata. An omitted or empty asset list is not serialized, preserving asset-free M1 project.json and ZIP behavior.
- A metadata-only custom revision copies all validated composition files without following symlinks and verifies every asset against its manifest. Existing revision files and library versions are never modified.
- Before capture, the worker checks each staged file against the revision hash, copies only those files into the sandboxed `composition/assets/`, and lets the existing browser file-URL allowlist serve those staged assets. The source ZIP contains `index.html`, `project.json`, `manifest.json`, and each pinned `assets/<id>-v<version>.<ext>` file, all hash-verified.
