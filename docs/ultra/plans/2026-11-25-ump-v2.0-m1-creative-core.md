# UMP v2.0 M1 — Creative Core Implementation Plan

**Goal:** Add a job-owned, seekable custom-composition path that runs safely on the profiled VM and produces original vertical MP4s without routing them through fixed cards or mandatory narration.

**Architecture:** Extend the existing job/revision and approval system with a small custom-composition branch; keep the v1 HyperFrames/preset path intact. Execute arbitrary scene HTML in a clean, network-denied systemd user unit, use Landlock for filesystem access, place writable capture state in a per-run `/dev/shm` directory bounded by cgroup memory, and stream PNG frames to FFmpeg instead of storing raw frames. Use the native recorder for custom HTML and retain HyperFrames for compatible legacy jobs.

**Tech stack:** Python 3.11.16; Node 22.22.2; Playwright Core 1.65.1; Chrome 156.0.8078.47 / SwiftShader; FFmpeg 6.1.1; HyperFrames 0.9.72 for the legacy path; Linux Landlock ABI 4; transient user systemd units; `unittest`.

**Spec:** `docs/ultra/specs/2026-11-25-ump-v2.0-master-blueprint.md`.

## Global Constraints

- The approved v2.0 blueprint is authoritative; keep v1 projects, snapshots, approvals, fixtures, and renderer behavior compatible.
- Custom composition is the default for new creative work; presets and the card builder remain optional legacy compatibility, not an action or content ceiling.
- Default final canvas is 1080×1920 at 30 FPS. Frame `n` is evaluated at `n/fps`; frame ranges are end-exclusive and total duration is `duration_frames/fps`.
- No Blender, paid service, heavyweight local image model, forced narration, forced subtitle, forced research, or mandatory source card. ADR-010 Series Continuity Engine remains deferred.
- Scene code and imported material are untrusted: no Hermes credentials, no network during capture, deny-by-default filesystem access, bounded CPU/RAM/processes/time/storage, strict path validation, and fail-closed isolation.
- Use one master clock and explicit absolute-time seek. Do not use per-frame randomness, wall-clock time, or accumulated delta as captured scene state.
- `MemoryAccounting=yes` is required with `MemoryMax` on this VM. A 64 MiB memory-accounted unit was OOM-killed while writing about 59 MiB to `/dev/shm`; without explicit accounting the same limit did not constrain the test.
- `TemporaryFileSystem=/tmp:rw,size=16M` fails on this user manager with `226/NAMESPACE` (`Operation not supported`). Use Landlock plus a run-private directory under `/dev/shm`, with the cgroup memory cap bounding tmpfs use; do not grant writable access to all of `/tmp` or `/dev/shm`.
- The current root filesystem has about 1.4 GB free. Do not write raw PNG sequences to disk, install WhisperX/models, or run concurrent large renders. Serialize custom renders.
- No merge to `main`, production-plugin replacement, deployment, publishing, paid-service use, or destructive migration without explicit approval.

## Rulings

- The supplied public ChatGPT share corroborates the operator’s mobile-first vertical/web-rendered, hybrid creative direction, no-Blender constraint, flexible safe-zone decision, and deferred series continuity. Its public view exposes the operator’s prompts and processing-time placeholders, not the assistant’s answers; the approved blueprint remains the complete design authority.
- Use the native recorder for arbitrary custom HTML because it can call the explicit seek contract and stream capture output. HyperFrames remains unchanged for the existing compatible path; do not replace it globally.
- Stream PNG screenshots from Playwright over stdout into FFmpeg. This removes raw-frame disk growth and lets the untrusted browser write only to its per-run tmpfs workspace.
- Apply a single global render lock: the 2 GiB unit cap is per run, so concurrent runs could otherwise exceed the VM’s verified available memory.
- Initial M1 demonstration limit: 60 seconds per custom composition, enough for the longest 45-second M5 benchmark while bounding arbitrary work. This is a resource guard, not a genre or product limit.

## Review Focus

1. **Isolation is weaker than the report claims.** Verify config-file reads, outside writes, AF_INET sockets, network loads, tmpfs growth, memory cap, timeout, and cleanup in the actual transient unit.
2. **Custom jobs silently fall back to cards or presets.** Prove the worker consumes the revision-owned `composition/index.html` with no call to `_cards`, `build_project`, or `prepare_audio`.
3. **Seek and frame count drift.** Test cold load, repeated/nonsequential/reverse seek, missing `ready`/`seek`, a blank frame, and exact end-exclusive frame count after FFmpeg encode.
4. **Mode/approval regression.** Autonomous custom jobs may proceed after the agent’s technical/visual review without impersonating operator approval; collaborative defaults to a preview checkpoint; directed mode uses only declared checkpoints (an omitted list defaults to preview, while an explicit empty list disables it). Any required approval remains bound to the current revision/artifact; legacy gates stay unchanged.
5. **Source or preview artifact is missing, stale, or escapes the run.** Verify source ZIP hashes, artifact paths, failed-run non-publication, and that editing HTML invalidates old preview/final approval.
6. **Technically valid but visually slide-like output.** Review actual normal-speed MP4 and action-boundary frames; diagnose and correct real issues, not just increase pixel activity.

**Interfaces:**
- `create_workspace(run_id) -> Path` creates a mode-0700 per-run directory under `/dev/shm` and returns it.
- `start_isolated(argv, *, workspace, read_paths, timeout_s) -> (Popen, unit_name)` returns a binary stdout pipe for PNG capture; the transient unit has a clean environment and bounded lifecycle.
- `wait_isolated(process, unit_name, timeout_s) -> int` stops the exact systemd unit on timeout, reaps the process, and returns a checked exit status.
